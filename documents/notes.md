# Notes

## Environment / toolchain

- Repo lives in WSL (`\\wsl.localhost\Ubuntu\home\mooin\decomps\pokemon-venture`). Git from the Windows side fails with "dubious ownership"; use `git -c safe.directory=* ...` (or run git inside WSL).
- Build: `make -j$(nproc)`. Tests: `make check -j` (filter with `make check TESTS="Spikes"`); see `docs/tutorials/how_to_testing_system.md`. Tests live in `test/` (battle tests are the bulk, under `test/battle/`).
- Upstream's own docs are in `docs/` (mdbook); `docs/tutorials/` has how-tos for new Pokémon, moves, trainers, FRLG, follower NPCs, DexNav, etc.
- The test heap is not zeroed between tests, and `make check` shares processes between tests by cost, so adding a test can change which tests share one. `Test_LoadMap` leaves state that made `Battle strings` time out depending on grouping (root cause never found), so it calls `Test_RestartAfterTest` (ROM restart before the next test; the restart replays cost assignment honoring the `TESTS=` filter). A `TIMEOUT` followed by `malloc.c:119` and gigabytes of `Illegal opcode` output is the runner aborting a test, not heap corruption; cap logs with `| head -c`.
- `test/e2e` gotchas (design in `design_dev.md`): savestates embed ROM addresses (cache keyed by ROM hash); stored function pointers need the Thumb bit (`| 1`); node-mgba has `write8` only; static symbols are absent from the `.map`; the message prompt blinks (masked); `import()` of a UNC path needs `pathToFileURL`; Node exists on Windows only (use PowerShell); Windows mGBA 0.10.5 has no `--script` flag and `-s` is frameskip.
- Map-loaded tests (`include/test/map_loaded.h`): the map load calls `MoveSaveBlocks_ResetHeap`, wiping the runner's heap state (the harness saves and re-allocates it), and leaves `gMain.callback2` at `CB2_Overworld` (the runner hangs until TIMEOUT unless `ReinitCallbacks()` runs). Large maps spawn only NPCs near the player (`Test_LoadMapAt`); `Test_FindObjectByScript` matches by local id because wandering NPCs move; a hinter's text reaches `gStringVar4` before `lock` finishes, so wait for the message box. `Test_MgbaPrintf` has no `%x`, which also shifts later args. Debug a silent hang by running `tools/mgba/mgba-rom-test` on a patched copy of the ELF (`patchelf gTestRunnerArgv`/`gTestRunnerHeadless`) and grepping the log for `Debug:`.
- Field-input tests: `Test_RunFieldFrames` runs `CB1_Overworld`, but the warp-in fade never finishes without VBlank, so controls stay locked until the test calls `UnlockPlayerFieldControls()`; `Test_FinishWarp` calls `TransferPlttBuffer` each frame for the same reason. Scripted `walk_*` movement ignores collisions, while the scene runner's search does not (a door tile is impassable in the map grid). Test builds have almost no EWRAM left: a few hundred bytes of test buffers broke the link.
- Build speed: the pipeline is `cpp | preproc | cc1 | as`, so ccache and PCH can't wrap it; `tools/cc1cache.sh` (Makefile `CC1CACHE`, set empty to disable) caches cc1 output in `~/.cache/pokemon-venture-cc1` (trim with `find -atime +14 -delete`) and prints warnings only on a miss. `src/data/*` headers are each included by one TU, so extracting them saves nothing; `pokemon.c` (cc1 37 s) and `battle_util.c` (22 s) are the critical-path outliers, fixable only by splitting them.
- Test speed: plain `make check` is single-process (the runner spawns one emulator per `make -j` job). `PASSES_RANDOMLY(p, n, TAG)` reruns the whole battle once per value of the tagged `RandomUniform` range (`n` is only the expected-ratio denominator), so wide rolls are slow. Fix: move the roll-to-outcome logic into a pure function tested by a plain `TEST`, and fix rolls with `WITH_RNG` (done for `GetEffectSporeOutcome`). Plain `TEST`s in `test/battle/*.c` can't use `PARAMETRIZE` (battle.h redefines it).

## Documentation layout

- `design.md` is an index plus principles; detail is in `design_*.md`, each with its own "Alternatives considered". Cite sections as file plus heading (`design_story.md, "Main plot planner"`); a quoted heading that lives in another file carries the file name.
- `Emerald.md` is one entry per county (city, gym, theme, places, planner steps with done-when predicates, storage); the old separate county, theme, gym, city-data, kinds, step-table and predicate tables were merged into it. The McGuffin chain, buckets and levels live in `Emerald_walkthrough.md`.
- `remaining_work.md` holds only open work: design-only questions live in each `design_*.md` "Open questions" section, and `tools/misc/check_remaining_work.py` (run by `make check`) fails on prose lines or lines over 400 characters, so every item can be deleted whole.

- `ld_script_test.ld` named `src/m4a.o` and `src/libisagbprn.o`.

## Misc environment and test limits

- Running tests: use `make check -j4` (all 12 cores plus a misbehaving ROM exhausts WSL's 7.9 GB; add `ulimit -v`). Upstream worktree for comparison: `~/decomps/pv-master` (outside the repo).
- Kanto (FRLG) content is in the repo: 419 `data/maps/*_Frlg` maps (incl. Sevii Islands) with full scripts, Kanto wild encounters in `wild_encounters.json`, `src/data/trainers_frlg.*`. Built only by `make firered`/`leafgreen` (`docs/tutorials/how_to_frlg.md`); `tools/mapjson` drops maps whose `region` differs from the build, so the Emerald ROM cannot reach them.
- `core.filemode=false` is set in this clone's `.git/config` (local, untracked) because Windows git over `\\wsl.localhost` sees every executable as `100644`. New executable scripts need `git update-index --chmod=+x <file>`.
- In the test build `gTrainers` is a stub (`test/test_runner_battle.c`, `battle/trainer_control.h`), so tests cannot read real trainer parties; check real trainer data offline against `src/data/trainers.party`.
- `RUN_OVERWORLD_SCRIPT` runs only specials and variable commands (no `lock`/`faceplayer`/`waitmessage`/objects); scripts with those run via `Test_LoadMap`. NPC bindings are tested by reading script bytes (`goto`/`call` are opcode + 4-byte pointer, `setvar` is opcode + 2 + 2) and `events->objectEvents[].script` (`test/pokemon_center_news.c`).
- Scene tests: object coordinates include `MAP_OFFSET` (7), so compare `currentCoords` with `+ MAP_OFFSET`.
- Scene path search zeroes the NPC's wander `range` while it runs: `GetCollisionAtCoords` returns `COLLISION_OUTSIDE_RANGE` for it though scripted walks ignore it.
- Littleroot twin scenes: set the stage var before `Test_LoadMapAt`, because `OnTransition` places the twin by it.
- Message tests must press A on a timer regardless of `IsFieldMessageBoxHidden` (it reads hidden while `waitbuttonpress` waits).
- Headless tests cannot run `Std_ObtainItem` (never returns; likely `showitemdescription` or the fanfare wait without VBlank) or a real battle: give scenes are stepped from C, battle steps only check the configured params.
- `ScriptContext_IsEnabled` is false while a script waits on a menu: scene tests run a fixed frame budget and stop on `gSpecialVar_Result == SCENE_RESULT_END`; list menus read `newAndRepeatedKeys` (`Test_PressKeys` sets it). Test builds are short of EWRAM: walk paths share one `sWalkDirs` buffer.
- Rejected: debug "checkpoints" (snapshot flags and vars per key item or badge, restore from a menu); emulator save states already do this, and an in-ROM save file needs new save-sector handling.
- `test/e2e` `Lilycove City: the hinter Man3` failed at the box frame pixels (text identical) on 2026-11-15, while the Mossdeep tests passed; not investigated.
- Two-state vars to flags: `map_script_2` and `coord_event` can test only a var, so a var that guards one stays a var unless the map's on-transition script copies the flag into `VAR_TEMP_0` (done for `SS_TIDAL_SCOTT_STATE`, `HAS_ENTERED_BATTLE_FRONTIER`; temp vars are cleared before on-transition runs). The remaining two-state vars are in vars.md. Renumbering shifted every minigame/engine/legacy var address, so old saves misread them. `make check` does not run these scripts: play the SS Tidal Scott scene, the Battle Frontier gate greeting, the Latios/Latias TV choice and the Route 128 Kyogre scene (`FLAG_KYOGRE_AWAKENED_SCENE`) once in the emulator. Legacy vars above `ROUTE128_STATE` shifted down one address, so old saves misread them.
