# Notes

## Environment / toolchain

- Repo lives in WSL (`\\wsl.localhost\Ubuntu\home\mooin\decomps\pokemon-venture`). Git from the Windows side fails with "dubious ownership"; use `git -c safe.directory=* ...` (or run git inside WSL).
- Build: `make -j$(nproc)`. Tests: `make check -j` (filter with `make check TESTS="Spikes"`); see `docs/tutorials/how_to_testing_system.md`. Tests live in `test/` (battle tests are the bulk, under `test/battle/`).
- Upstream's own docs are in `docs/` (mdbook); `docs/tutorials/` has how-tos for new Pokémon, moves, trainers, FRLG, follower NPCs, DexNav, etc.
- The test heap is not zeroed between tests, and `make check` shares processes between tests by cost, so adding a test can change which tests share one. `Test_LoadMap` leaves state that made `Battle strings` time out depending on grouping (root cause never found), so it calls `Test_RestartAfterTest` (ROM restart before the next test; the restart replays cost assignment honoring the `TESTS=` filter). A `TIMEOUT` followed by `malloc.c:119` and gigabytes of `Illegal opcode` output is the runner aborting a test, not heap corruption; cap logs with `| head -c`.
- `test/e2e` gotchas (design in `design_dev.md`): savestates embed ROM addresses (cache keyed by ROM hash); stored function pointers need the Thumb bit (`| 1`); node-mgba has `write8` only; static symbols are absent from the `.map`; the message prompt blinks (masked); `import()` of a UNC path needs `pathToFileURL`; Node exists on Windows only (use PowerShell); Windows mGBA 0.10.5 has no `--script` flag and `-s` is frameskip.
- Map-loaded tests (`include/test/map_loaded.h`): the map load calls `MoveSaveBlocks_ResetHeap`, wiping the runner's heap state (the harness saves and re-allocates it), and leaves `gMain.callback2` at `CB2_Overworld` (the runner hangs until TIMEOUT unless `ReinitCallbacks()` runs). Large maps spawn only NPCs near the player (`Test_LoadMapAt`); `Test_FindObjectByScript` matches by local id because wandering NPCs move; a hinter's text reaches `gStringVar4` before `lock` finishes, so wait for the message box. `Test_MgbaPrintf` has no `%x`, which also shifts later args. Debug a silent hang by running `tools/mgba/mgba-rom-test` on a patched copy of the ELF (`patchelf gTestRunnerArgv`/`gTestRunnerHeadless`) and grepping the log for `Debug:`.
- Field-input tests: `Test_RunFieldFrames` runs `CB1_Overworld`, but the warp-in fade never finishes without VBlank, so controls stay locked until the test calls `UnlockPlayerFieldControls()`; `Test_FinishWarp` calls `TransferPlttBuffer` each frame for the same reason. Scripted `walk_*` movement ignores collisions, while the scene runner's search does not (a door tile is impassable in the map grid). Test builds have almost no EWRAM left: a few hundred bytes of test buffers broke the link.
- Build speed (measured with `-ftime-report`, full test-build rebuild at `-j12` = 131 s, `-j4` would be ~340 s): the pipeline is `cpp | preproc | cc1 | as`, so ccache and PCH can't wrap it. `tools/cc1cache.sh` (Makefile `CC1CACHE`, empty to disable; cache in `~/.cache/pokemon-venture-cc1`, gzipped, trim with `find -atime +14 -delete`) caches cc1 output by preprocessed text: warm rebuild 72 s, after `touch vars.h` 81 s. Warnings print only on a miss. `#include "global.h"` alone costs ~0.7 s per TU (500 KB preprocessed, ~330 headers) over 1380 TUs; flags.h, easy_chat.h, map_groups.h, cries.h, species.h are the largest per-TU costs. `src/data/*` headers hold the big arrays but each is included by exactly one TU, so extracting them saves nothing; `pokemon.c` (10 MB preprocessed, cc1 37 s) and battle_util.c (22 s) are the critical-path outliers, fixable only by splitting those files.
- Test speed (profile via timestamps on `make check -j8` output; 5,716 tests = 5,660 CPU-s, 766 s wall): the hydra runs one emulator per `make -j` job, so plain `make check` is single-process. 58 tests over 10 s took 47% of CPU: `PASSES_RANDOMLY(p, n, TAG)` reruns the whole battle with animations once per value of the tagged `RandomUniform` range (the `n` is only the expected-ratio denominator; Gen 3 Effect Spore rolls 0-299), and passes if the pass fraction is within 2% of p/n. Fix pattern: extract the roll-to-outcome logic into a pure function tested by a plain `TEST`, and fix rolls in battle tests with `WITH_RNG` (done for Effect Spore, `GetEffectSporeOutcome`). Plain `TEST`s in `test/battle/*.c` can't use `PARAMETRIZE` (battle.h redefines it).
